# HTTP: 1.0 vs. 1.1 vs. 2.0 vs. 3.0

## Overview
HTTP (HyperText Transfer Protocol) has evolved significantly since its inception, with major versions introducing performance improvements, security enhancements, and new capabilities. This document compares the key features and differences between HTTP/1.0, HTTP/1.1, HTTP/2.0, and HTTP/3.0.

## HTTP/1.0 (1996)

### Key Features
- **Basic Request-Response Model:** One request, one response per connection
- **Connection Closing:** New TCP connection for each request
- **Simple Headers:** Basic content negotiation and caching
- **Methods:** Supports GET, HEAD, POST methods

### Limitations
- **Connection Inefficiency:** High overhead from creating new connections
- **No Host Header:** Cannot host multiple domains on single IP address
- **Limited Caching Controls:** Basic caching mechanisms only

### Use Case
Simple static websites with few resources

## HTTP/1.1 (1997)

### Key Features
- **Persistent Connections:** Keeps TCP connections open for multiple requests
- **Pipelining:** Allows sending multiple requests before receiving responses (limited implementation)
- **Host Header:** Enables virtual hosting (multiple domains on one IP)
- **Enhanced Methods:** Added PUT, DELETE, OPTIONS, TRACE
- **Improved Caching:** More cache control options
- **Chunked Transfers:** Allows streaming of content
- **Content Negotiation:** Better support for different formats

### Improvements Over HTTP/1.0
- **Reduced Latency:** Fewer connection establishments
- **Better Resource Management:** More efficient use of TCP connections
- **Expanded Capabilities:** More HTTP methods and header options

### Use Case
Dynamic websites, e-commerce platforms, content management systems

## HTTP/2.0 (2015)

### Key Features
- **Binary Protocol:** More efficient parsing compared to text-based protocols
- **Multiplexing:** Multiple requests/responses over single connection
- **Header Compression (HPACK):** Reduces overhead
- **Server Push:** Server can send resources before client requests them
- **Stream Prioritization:** Allows resources to be loaded in optimal order
- **Flow Control:** Better management of data transmission

### Improvements Over HTTP/1.1
- **Performance Boost:** Significantly faster page loads
- **Reduced Latency:** Eliminates head-of-line blocking
- **Lower Bandwidth Usage:** Compressed headers and efficient protocol
- **Concurrent Downloads:** True parallel processing of requests

### Use Case
Modern web applications, SPAs, high-traffic sites, mobile-optimized sites

## HTTP/3.0 (2020)

### Key Features
- **QUIC Protocol:** Based on UDP instead of TCP
- **Built-in Encryption:** TLS 1.3 by default
- **Improved Connection Migration:** Better handling of network changes
- **0-RTT Connection Establishment:** Faster connection setup
- **Independent Streams:** Stream errors don't block other streams
- **Better Packet Loss Recovery:** Improved performance on unreliable networks

### Improvements Over HTTP/2.0
- **Reduced Latency:** Faster connection establishment
- **Better Mobile Performance:** Handles network transitions smoothly
- **Improved Reliability:** Better performance on poor connections
- **Enhanced Security:** Modern encryption by default

### Use Case
Real-time applications, streaming services, mobile applications, IoT devices

## Key Differences Summary

| Feature | HTTP/1.0 | HTTP/1.1 | HTTP/2.0 | HTTP/3.0 |
|---------|----------|----------|----------|----------|
| Release Year | 1996 | 1997 | 2015 | 2020 |
| Protocol Base | TCP (text) | TCP (text) | TCP (binary) | UDP (QUIC) |
| Connection Model | New per request | Persistent | Multiplexed | Multiplexed |
| Header Compression | None | None | HPACK | QPACK |
| Encryption | Optional | Optional | Recommended | Mandatory |
| Server Push | No | No | Yes | Yes |
| Pipelining | No | Limited | N/A (multiplexed) | N/A (multiplexed) |
| Stream Prioritization | No | No | Yes | Yes |
| Connection Migration | No | No | No | Yes |
| Performance in Packet Loss | Poor | Poor | Moderate | Good |

## Performance Comparison

### Page Load Time (Relative)
- HTTP/1.0: Slowest (100%)
- HTTP/1.1: Improved (70-80% of HTTP/1.0)
- HTTP/2.0: Significantly faster (40-60% of HTTP/1.0)
- HTTP/3.0: Fastest, especially on unreliable networks (30-50% of HTTP/1.0)

### Number of Connections Required
- HTTP/1.0: One per resource
- HTTP/1.1: Multiple (typically 6-8 per domain)
- HTTP/2.0: Single connection
- HTTP/3.0: Single connection with better resilience

## Adoption Considerations

### When to Use HTTP/1.1
- Legacy system compatibility
- Simple websites with minimal resources
- When HTTP/2.0 implementation is not feasible

### When to Use HTTP/2.0
- Modern web applications
- Sites with many resources (images, scripts, stylesheets)
- When performance is important but HTTP/3.0 is not supported

### When to Use HTTP/3.0
- Mobile-first applications
- Real-time services
- Global audiences with varying network qualities
- Performance-critical applications

## Conclusion
The evolution of HTTP has been driven by the need for faster, more secure, and more efficient web experiences. Each version has introduced significant improvements addressing the limitations of its predecessors. As web applications become increasingly complex and users expect instantaneous responses, understanding the capabilities of each HTTP version helps developers choose the most appropriate protocol for their specific use cases.

HTTP/3.0 represents the current pinnacle of this evolution, but practical implementations often involve supporting multiple versions to ensure compatibility with all clients and browsers.
